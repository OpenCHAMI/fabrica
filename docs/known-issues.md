# Known Issues and Limitations

This document tracks known issues, limitations, and areas for future improvement in Fabrica.

## Feature Toggle Limitations

### Authentication (Auth)

**Issue**: The authentication feature has the same architectural limitation that metrics had before v0.5.0.

**Details**:
- `cmd/server/main.go` contains `{{if .WithAuth}}` conditionals that are set during `fabrica init`
- Toggling `features.auth.enabled` in `.fabrica.yaml` after initialization requires manual `main.go` updates
- The auth middleware and endpoints are only included in `main.go` if `--auth` was specified during init

**Workaround**:
1. Manually add/remove auth middleware calls in `main.go`, or
2. Reinitialize the project with the desired auth setting

**Solution Planned**: Future branch will implement runtime detection (same pattern as metrics)
- Track issue: TBD
- Target version: TBD

**Files Affected**:
- `cmd/server/main.go` - Contains `{{if .WithAuth}}` blocks
- `cmd/server/auth_helpers_generated.go` - Always generated, returns nil when disabled

### Other Features

| Feature | Runtime Toggle | Notes |
|---------|----------------|-------|
| **Storage** | ❌ No | Always required for CRUD APIs; type can be changed (requires migration) |
| **Events** | ✅ Yes | Uses runtime detection pattern via `initializeEventingAndReconciliation()` |
| **Reconciliation** | ✅ Yes | Uses runtime detection pattern (requires Events) |
| **Validation** | ✅ Yes | Configuration-based via `.fabrica.yaml`, no code changes needed |
| **Conditional** | ✅ Yes | Configuration-based via `.fabrica.yaml`, middleware is conditional |
| **Metrics** | ✅ Yes | Uses runtime detection pattern (as of v0.5.0) |
| **Auth** | ❌ No | Requires `main.go` regeneration or manual edits (see above) |

## API Versioning

### Hub/Spoke Version Changes

**Issue**: Changing the storage (hub) version or adding/removing API versions requires careful migration.

**Details**:
- The storage version determines the internal representation of resources
- Changing hub versions may require data migration
- Conversion functions must be manually implemented for new spoke versions

**Workaround**:
- Plan your versioning strategy carefully before adding resources
- Use `apis.yaml` to configure versions before running `fabrica generate`
- Implement conversion functions in `apis/<group>/<version>/conversion.go`

**Documentation**: See [API Versioning Guide](./guides/versioning.md)

## Storage Backend Changes

### Switching Between File and Ent Storage

**Issue**: Changing storage backends (file ↔ ent) requires data migration.

**Details**:
- File storage uses JSON files in `./data/`
- Ent storage uses a relational database
- No automatic migration tool exists

**Workaround**:
1. Export data from old backend: `./server export > backup.json`
2. Change `features.storage.type` in `.fabrica.yaml`
3. Run `fabrica generate`
4. Import data to new backend: `./server import < backup.json`

**Limitations**:
- Export/import only works with Ent storage (as of v0.4.0+)
- Manual data transformation may be needed for complex schemas

## Template Customization

### Generated Files Are Overwritten

**Issue**: Files marked with `// Code generated by Fabrica. DO NOT EDIT.` are regenerated on every `fabrica generate`.

**Details**:
- Customizations to generated files will be lost
- This includes handlers, routes, models, and middleware

**Workaround**:
- Use custom middleware or wrapper functions for customizations
- Extend generated types with additional methods in separate files
- Use the `// +fabrica:skip` annotation to prevent regeneration (limited support)

**Best Practice**: Keep customizations in separate files that are not generated.

## Performance

### Large Numbers of Resources

**Issue**: Projects with 50+ resources may experience slow generation times.

**Details**:
- Template execution is currently sequential
- Ent schema generation can be slow for large schemas

**Workaround**:
- Use `--handlers`, `--storage`, etc. flags to regenerate only what changed
- Consider splitting into multiple Fabrica projects (microservices)

**Future Improvement**: Parallel generation planned for future release.
